# Jade AI 개발방법론 (Jade AI Development Guide)

> **"개발 지식이 없어도 따라 하는 11단계 가이드"**  
> AI가 문서와 코드를 만들고, 사람이 확인하고 책임지는 실무 표준 개발 방법론  
> **미래차사업본부 서비스전략그룹 전략개발1팀 Jade.K · AUTOCRYPT**

---

## 📌 개요

본 가이드는 고객 요구사항을 빠짐없이 반영한 결과물을 생성형 AI를 활용하여 신속하고 일정한 품질로 구축하기 위한 **표준 개발 프로세스 매뉴얼**입니다.

### 3대 핵심 원칙
1. **AI는 초안을 만든다**: AI의 산출물은 언제나 '초안'이며, 확인과 최종 결정·책임은 사람이 담당합니다.
2. **원문 근거 대조 & 교차 검증**: 과업지시서 및 고객 요구사항 원문과의 대조, 다중 AI 모델(NotebookLM, Claude, Gemini) 교차 검증을 필수화합니다.
3. **전 과정 문서화 & 추적 관리**: 요구사항 추적표(RTM)를 중심으로 모든 요구사항이 설계, 개발, 테스트까지 누락 없이 이어지도록 관리합니다.

## 🔄 11단계 표준 개발 프로세스 (V-Model)

```
[ 분석 (Analysis) ] ──▶ [ 설계 (Design) ] ──▶ [ 개발·검증 (Dev/Test) ] ──▶ [ 납품 (Delivery) ]
 1. 요구사항 분석       5. 아키텍처 구성         7. 개발 (AI 보조)         10. 최종 검증(UAT)
 2. PRD 작성            6. 서비스 디자인 정의    8. 단위 테스트            11. 산출물 제출
 3. SRS 작성                                     9. 통합 테스트
 4. 고객 협의·반영
```

### 1. 분석 (Analysis)
* **01. 요구사항 분석**: 과업지시서/RFP에서 기능·비기능 요구사항 추출 및 번호화, 불명확 사항 질의서 도출
* **02. PRD(제품요구사항 정의서) 작성**: 무엇을, 왜 만드는지 제품 관점의 목표, 사용자, 범위 및 기술 조건 정의
* **03. SRS(소프트웨어 요구사항 명세서) 작성**: 개발 및 테스트의 기준이 되는 상세 명세화, RTM(요구사항 추적표) 초안 수립
* **04. 고객 협의·반영**: 고객 인터뷰 및 협의를 통해 변경사항을 확정하고 SRS/RTM 갱신

### 2. 설계 (Design)
* **05. 전체 아키텍처 구성**: 시스템 구성도, 데이터 모델(ERD), 인터페이스 및 보안/성능 구조 설계
* **06. 서비스 구성·디자인 방향 정의**: 메뉴 구조, 화면 흐름도(Wireframe/IA), 디자인 방향 수립

### 3. 개발 및 검증 (Development & Testing)
* **07. 개발**: AI 코딩 지원을 활용한 빠른 초안 작성, 1~2주 단위 요구사항 대조, 코드 리뷰 및 보안 점검
* **08. 단위 테스트**: SRS 기능 명세 기반 테스트 시나리오/코드 생성 및 정상/예외 케이스 검증
* **09. 통합 테스트**: 업무 흐름 관통 시나리오, 연계 시스템 테스트, 성능/부하 및 보안약점 진단

### 4. 납품 (Delivery)
* **10. 최종 검증·준공 및 안정화**: 고객 인수 시험(UAT) 진행, RTM 기반 요구사항 100% 충족 확인 및 준공 확인서 수령
* **11. 과업지시서 산출물 작성·제출**: 발주처 요구 산출물 목록 전수 점검, 최신화 및 최종 제출

## 🏛️ 전체 시스템 & AI 파이프라인 아키텍처 (Architecture Diagram)

본 방법론의 **5단계(전체 아키텍처 구성)**에서 수립하는 엔터프라이즈 레퍼런스 모델과 AI 개발 파이프라인 구조입니다.

### 1. 시스템 N-Tier 엔터프라이즈 계층 구성도
```
[ 1. Presentation Layer (클라이언트) ]
  ├── 🖥️ 웹 통합 관제 대시보드 (React 18 + TypeScript + TailwindCSS SPA)
  ├── 📱 모바일 필드 관제 웹 (PWA 반응형 웹)
  └── ⚙️ 시스템 운영·관리자 콘솔 (RBAC 기반 대시보드, 감사 이력, RTM 추적)
         │  ▲  (HTTPS / TLS 1.3 / WSS WebSocket Secure)
         ▼  │
[ 2. Gateway & Security Layer (경계 보안 및 단일 진입점) ]
  ├── 🛡️ Nginx Reverse Proxy (SSL 오프로딩, 정적자원 Gzip, L7 로드밸런싱)
  ├── 🔒 Web Application Firewall (WAF, SQLi/XSS 차단, DDoS Rate Limiting)
  └── 🔑 API Gateway & Auth Broker (Spring Security, JWT Bearer, 2FA OTP)
         │  ▲  (/api/* 내부 라우팅)
         ▼  │
[ 3. Application / WAS Layer (비즈니스 코어 - 전자정부 표준프레임워크 4.0) ]
  ├── 📡 디바이스 & FMS 관제 서비스 (3초 단위 텔레메트리 파싱, 이상 상태 감지)
  ├── 💼 핵심 비즈니스 & 정산 엔진 (사용자/장비 관리, 통계 배치 집계, 이벤트 알람)
  └── ⚡ 실시간 이벤트 브로커 (Spring WebSocket + Redis Pub/Sub 브로드캐스팅)
         │  ▲  (HikariCP 커넥션 풀 / 비동기 큐)
         ▼  │
[ 4. Data & Persistence Layer (데이터 및 저장소) ]
  ├── 🗄️ PostgreSQL 15 (ACID 관계형 마스터 DB, 메타데이터, JSONB 이력 관리)
  ├── 🗺️ PostGIS (GPS 공간 좌표 인덱싱(GiST), 지오펜싱, 반경 고속 탐색)
  ├── ⚡ Redis 7.0 Cluster (실시간 관제 최신 캐시, 세션 클러스터링, 분산 락)
  └── 📦 MinIO / S3 Storage (UAT 시험 성적서, 준공 산출물 패키지, 감사 로그)
         │  ▲  (REST Client / TCP / MQTT / SFTP)
         ▼  │
[ 5. External Integration & Edge Layer (외부 연계 및 하드웨어) ]
  ├── 🚗 FMS 단말기 / IoT 센서 (차량 OBD-II, GPS 텔레메트리 스트리밍)
  ├── 🌐 공공데이터포털 OpenAPI (기상청 실시간 날씨, 국토교통부 표준 링크)
  └── 🏢 고객사 레거시 기간계 (인사/조직 DB 연계, EAI/ESB, 배치 정산 전송)
```

### 2. AI 표준 개발 파이프라인 & RTM 품질 스파인 (Quality Spine)
```
[ 1. 과업 입력 ]  과업지시서(RFP), 제안요청서, 고객 질의/인터뷰
       │
       ▼
[ 2. 대용량 독해 ]  NotebookLM  ──▶ 수백 쪽 원문 전수 독해, 요구사항 식별 및 원본 근거 쪽수 매핑
       │
       ▼
[ 3. 명세 및 구현 ]  Claude      ──▶ PRD/SRS 표준 명세화, N-Tier 코드 스캐폴딩, 단위테스트 코드 생성
       │
       ▼
[ 4. 교차 검증 ]  Gemini      ──▶ 산출물 누락·모순·환각 크로스체크, 대용량 컨텍스트 종합 무결성 진단
       │
       ▼
[ 5. 사람 책임 ]  엔지니어/PM  ──▶ 원문 1:1 대조 확인, 고객사 협의결과서 확정, 산출물 최종 품질 책임

======================= 🔗 RTM 중심 엔드투엔드 무결성 추적 스파인 =======================
 [과업요구: REQ-01] ──▶ [기획명세: SRS-5.2] ──▶ [설계도: ARCH 3장] ──▶ [코드: Commit] ──▶ [시험: TC-045] ──▶ [인수: UAT 통과]
   ※ 모든 과업은 고유 ID로 1:1 직결되어 중간 누락이나 미구현을 원천 차단합니다.
```

## 📊 11단계 엔드투엔드 전체 업무 흐름도 (End-to-End Business Workflow)

발주처 고객, PM/기획자, 개발자, QA 검증자의 **4대 주체별 협업 수영레인(Swimlane)** 및 실무 트랜잭션 흐름도입니다.

### 1. 4대 주체별 전주기 협업 수영레인 (Swimlane View)
```
[Phase]      [고객사(발주처)]      [PM/기획자(SA)]       [개발자(Dev)]         [QA/검증자(Tester)]
────────────────────────────────────────────────────────────────────────────────────────────
01. 분석     과업지시서 전달 ──▶   요구사항 전수 추출     기술 스택 검토
(1~4단계)    착수 보고 회의        (NotebookLM)
                                       │
                                   PRD/SRS 초안 작성                          검증 기준선 검토
                                   RTM 초안 수립(Claude)                      (테스트 가능성 확인)
                                       │
             고객 질의 회신  ◀──▶  고객 질의서 인터뷰
             협의결과서 확정 ──▶   SRS & RTM 최종 승인
────────────────────────────────────────────────────────────────────────────────────────────
02. 설계     메뉴/IA 확인          화면 흐름도 기획  ◀──▶ 시스템 N-Tier 설계     테스트 케이스(TC)
(5~6단계)    디자인 방향 승인 ◀──  화면설계서 작성        ERD / I/F 정의서       사전 설계
────────────────────────────────────────────────────────────────────────────────────────────
03. 개발/    중간 데모 참관        스프린트 백로그 관리   AI 보조 스프린트 개발 ──▶ 단위 테스트 실행
검증         (1~2주 단위)                                 시큐어 코딩 자가진단   (정상/예외 전수)
(7~9단계)                                                 코드 리뷰 통과               │
                                                                 ▲            통합·부하·보안
                                                                 │            관통 테스트 수행
                                   결함 모니터링   ◀───  결함 조치/보완 ◀───  결함 리포트 발행
────────────────────────────────────────────────────────────────────────────────────────────
04. 납품     UAT 인수시험 입회 ◀─  UAT 시나리오 총괄      운영서버 배포          UAT 실환경 가이드
(10~11단계)  RTM 100% 충족 확인    과업 산출물 패키징     개발 산출물 최신화     RTM 100% 검증서 발급
                   │                   │
             준공확인서 날인 ──▶   최종 납품서 제출 ──▶   운영 유지보수 이관
```

### 2. 실무 서비스 트랜잭션 처리 흐름도 (Core Transaction Flow)
```
[STEP 01: 사용자 요청]      Web/Mobile UI에서 관제 명령 및 텔레메트리 조회 요청 발생 (HTTPS/WSS)
         │
         ▼
[STEP 02: 게이트웨이 보안]   Nginx WAF 필터링 ──▶ Spring Security JWT 유효성 & 2FA 인가 확인
         │
         ▼
[STEP 03: 비즈니스 처리]    전자정부 WAS Core Service에서 비즈니스 도메인 규칙 수행 및 이벤트 분석
         │
         ▼
[STEP 04: 실시간 브로드캐스트] Redis Pub/Sub 및 WebSocket Session을 통해 전 관제 브라우저 즉시 전파
         │
         ▼
[STEP 05: DB 영속화 & 캐시]  PostgreSQL 트랜잭션 커밋 + PostGIS 좌표 갱신 + Redis 캐시 + 감사로그 적재
         │
         ▼
[STEP 06: 화면 갱신 & 피드백] 관제 지도 마커 실시간 깜빡임 및 성공 토스트 피드백 노출
```

### 3. 실무 3대 필수 협업 수칙
1. **🚨 회의록 없는 변경은 개발 금지**: 구두 협의는 반드시 `06_고객협의결과서_변경요청서_템플릿.md`로 공식 문서화 후 반영
2. **🔗 REQ ID 없는 코드는 불인정**: 모든 커밋과 테스트 케이스는 RTM의 `REQ-xxx` 고유 식별 번호와 1:1 직결 필수
3. **⚖️ V-Model 짝 점검 필수**: 왼쪽 설계서(PRD·SRS·아키텍처)를 수정했다면, 오른쪽 대응 테스트 시나리오(단위·통합·UAT) 동시 갱신

## 🔒 AI 사용 전 보안 수칙
1. **계약·보안 조건 확인**: 고객사 보안 규정 및 사업 계약서상 외부 AI 사용 허용 여부 사전 확인
2. **민감 정보 마스킹**: 개인정보, 시스템 내부 IP/망 구성 정보, 인증키/토큰/패스워드는 절대 업로드 금지
3. **학습 제외 계정 사용**: 기업용 엔터프라이즈 계정 또는 데이터 학습(Training)에 사용되지 않는 전용 설정 준수
4. **사용 이력 관리**: 어떤 문서와 코드가 어떤 도구를 거쳤는지 투명하게 기록 관리

## ⚡ Gemini AI 엔진 & ngrok 연동 (실전 PoC)

본 저장소에는 ngrok 터널(`https://stem-shifter-selected.ngrok-free.dev`) 및 로컬 환경에서 **Google Gemini 2.0 Flash AI 엔진**을 즉시 구동할 수 있는 경량 백엔드와 테스트 웹 UI가 포함되어 있습니다:

### 1. 구성 파일
* **`server_gemini.py`**: FastAPI 기반 초경량 Gemini 백엔드 서버 (CORS 완비, ngrok 무료 경고 바이패스 헤더 내장, 실시간 스트리밍 지원)
* **`test_client.html`**: 브라우저에서 바로 실행하는 실시간 대화형 테스트 대시보드
* **`.env.example`**: API 키 설정용 환경변수 템플릿

### 2. 빠른 실행 방법
```bash
# 1. 패키지 설치
pip install fastapi uvicorn google-genai pydantic

# 2. API 키 설정 (.env 파일에 GEMINI_API_KEY 입력 또는 환경변수 설정)
export GEMINI_API_KEY="AIzaSy..."   # Windows PowerShell: $env:GEMINI_API_KEY="AIzaSy..."

# 3. 로컬 서버 실행 (포트 8000)
python server_gemini.py

# 4. ngrok 터널 연결 (별도 터미널)
ngrok http 8000 --url=stem-shifter-selected.ngrok-free.dev

# 5. 테스트 클라이언트 실행
test_client.html 파일을 브라우저에서 열고 질의 테스트 진행
```
